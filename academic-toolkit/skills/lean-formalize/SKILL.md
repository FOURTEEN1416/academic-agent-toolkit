# Lean 形式化证明

把用户的数学命题落成一条**通过机器检验的 Lean 定理**，且命题含义保持不变。编译出一条带前提的条件引理只是进展；"完成"只看原始命题本身与实际动用的信任基础。

## 何时使用

满足任一条件才进入本技能：

- 用户点名 Lean、要求形式化证明，或要继续一个已有的 Lean 证明工程；
- 某个核心论断存在具体的不确定性——长依赖链、精细的归约、有限分类的覆盖——而形式化能实质支撑其正确性。

开工时先说明本技能要解决的那个证明义务，并在授权任务范围内推进。**难度本身不是形式化的理由**：普通推导与短证明留在普通证明流程（如 `proof-writer`）；不要把 Lean 变成每个数学结论的前置门槛。尊重用户选定的证明方法与 requested 工作规模。

## 环境前置检查（Lean 工具链，外部依赖）

本仓**不随带 Lean 工具链**（elan / lake / lean；Mathlib 可选）。任何编译、`#print axioms`、复现命令都依赖执行侧已装好的环境。开工前先探测：

```bash
lean --version && lake --version
```

- **探测失败**：立即按 TOOL_GAP 如实报告，指向本目录 `ASSET-GAP.md`，并停在该缺口上——**不得假装环境已备，不得用文字证明冒充机器验证，也不代用户安装全局软件**（除非用户明确授权）。仍可继续的部分（读题、固定含义、设计证明路线、写 Lean 草稿）可以推进，但一切"已验证"结论必须等到机器检验真实执行后才可宣称。
- **探测通过**：沿用工程既有的工具链与锁文件（`lean-toolchain`、`lake-manifest.json`），不擅自升级依赖或更换证明框架；API 一律对钉住的库版本解析。

## 评审独立性（A/B/C 检查点前置约定）

三个对抗评审检查点（A/B/C）都要求**评审者与执行者上下文独立**：评审者直接读原始材料，不接收执行者的结论、摘要或解读（契约见 `../shared-references/reviewer-independence.md`；零 APIKey 的执行侧按 `../_utils/independent_review_manual.md` 的降级办法执行）。执行侧可用的评审通道以当前宿主实际注册的工具为准，不写死任何供应商、配额、重试次数、代理或模型。评审通道不可用时，该检查点记 **pending**，证明工作继续推进；一份通过机检的定理与一份"所要求的评审全部完成"是两个独立交付物。用户点名多个评审家族时逐一获得并记录；同家族意见不能顶替另一家族。

## 核心工作流

```text
原始命题与 Lean 定义
  → A：跨家族对抗式命题对齐
  → 证明义务、表示选择与引理接口
  → Lean 实现 ↔ B：关键论证与输入连接的对抗评审
  → 实际输入接通；装配原始定理
  → 执行类型、定义与传递公理审计
  → C：最终导出结果的跨家族对抗评审
  → 可复现交付与研究状态更新
```

大型新证明工程必须走 A/B/C。续作时，未受影响的义务复用既有检查结论，只重查受影响部分。小型常规形式化的检查强度与命题重要性成比例；用户点名要跨家族评审时，小任务同样适用。

## 范围与入口

按用户要求的范围执行：实现、续作、审计或打包。

- **审计**：只检查并报告，不静默修复或弱化定理。
- **实现**：既要发展数学论证，也要写出 Lean 证明——检索相关文献与库结果、探索替代路线、补齐缺失引理；持续推进到剩余接口与顶层装配全部闭合，**不停在第一个编译通过的目标声明上**。

进场先读：权威命题、既有 Lean 入口、工具链与锁文件、最新进展记录；复用既有工程与文档命名。环境合用时不要重装工具、改依赖或另起炉灶。

证明路线已存在就沿用。**数学论证本身缺失**时，把该义务隔离出来交给普通证明流程（如 `proof-writer`）或自行推导：被委托的任务返回论证或剩余缺口，它不得反过来再调用本技能。语法自动化无法消解一条未证明的前提。不要承诺形式化或解决任意的公开问题。

### 起点判别

| 当前输入 | 第一个有用动作 |
|---|---|
| 只有一个数学命题 | 固定定义与量词，发展证明路线及第一个困难义务 |
| 一段文字证明 | 识别非平凡依赖，选 Lean 表示；先把缺失论证暴露出来再写码 |
| 半成品 Lean 工程 | 检查目标与真实调用方，读最近一次有用构建/报错记录，从最高未闭合连接继续 |
| 审计请求 | 读定义与导出类型，运行适用检查并报告；不静默修复目标 |
| 已完成证明待移交 | 核对当前入口与证据，准备可移植源码与命令；不重启数学搜索 |

尽早写明目标主模块、导出声明与当前下一义务。数学路线未知时，如实说明正在尝试哪个命题；**不能因为实现已开始就宣称可证**。工具/API 故障与数学论证缺失是两类问题，下一步不同。

## 1. 先固定含义，再实现

写一份简短数学规格（或引用既有规格）：

- 对象、定义域、量词、原始假设与结论；
- 便捷表示与原始对象之间的等价性；
- 用户对计算、外部证书与逻辑基础的约束；
- 打算用以表达并证明结果的 Lean 声明。

把**原始假设**与**归约引入的性质**分开。标出有限性、非空性、可判定性、正规化与下标约定会改变命题或需要桥接的位置。在真实定理上检查平凡真（vacuous）与量词失效，不要发明无关的边界情形。

在用户改变目标之前，原始命题始终是比对基线；为迁就实现而改写的"工作规格"不改基线。授权范围内的目标变更要显式记录；会话内已授权过的变更不必重复请示。修复若只得到更强假设或更弱结论，要指明已证变体与仍未闭合的原始义务；更强结果配上到原命题的蕴含式，也可确立原命题。

在真实定义体与提议目标上运行检查点 A：先要独立回译，再与原始数学比对（packet 与提示词见 [references/adversarial-review.md](references/adversarial-review.md)）。只看过预期文字的评审者，没有检验编码。

## 2. 先设计连接，再构建有用部件

画出从任意原始输入到结论的路径。每个实质性接口记录四元组：

| 声明/义务 | 假设什么 | 实际输入从哪来 | 证据/剩余缺口 |
|---|---|---|---|
| 一条条件性结果 | 它的额外假设 | 来自原始输入的某个具名构造或定理 | 当前状态 |

优先攻最高的未闭合连接。特别要区分三件事，三者可能各需独立证明：

1. 某公式或证书计算出想要的数；
2. 真实数学对象实现该公式/证书；
3. 计算出的事实蕴含原始结论。

把想要性质存成字段的结构体、外部给的概率界、或与结论等价的假设，都**不能免除构造该输入的义务**。

条件引理作为开发接口使用，并显式标注。不完整实验放在认证目标的依赖链之外；临时 `sorry` 永远以未完成姿态可见，不得混入最终目标审计。保持足够的中间编译以定位错误，但不把文件数或已证算术命题当完成度。

并行工作沿稳定的引理签名与模块所有权切分；给每个 worker 它的假设、结论、依赖与具体编译目标；结果先对真实调用方集成再记账。禁止并行 worker 为迁就自己的证明而静默重定义共享对象。

### 实现循环

实现或修复义务时读 [references/lean-working-loop.md](references/lean-working-loop.md)：搜索 → 真实调用方实验 → 诊断 → 修复的完整循环、表示选择与性能问题，附一个编译过的库应用示例。

1. 选一个能改变主定理可证范围的缺失连接或数学引理，写明精确 Lean 接口与调用方义务。
2. 先在钉住的库与工程内找现成结果；不熟的声明用 `#check` 本地试；能简化真实瓶颈时就用既有等价表示。
3. 实现该引理与一个真实使用点；编译受影响模块；集成后编译依赖它的下游目标。
4. 诊断第一条相关错误：elaboration/API 不匹配 → 本地修实现；假设缺失 → 推导它、换论证、或显式记为剩余数学义务。
5. 有限归约代价过高时，考虑一般计数引理、递推或更小的已检证书；**不得为让战术跑通而静默扩大信任基础**。
6. 遇到新的承重论证或接口时运行检查点 B；实现有效修复、编译，并就变更后的义务做后续评审。
7. 在既有台账更新声明、真实调用方、验证证据与剩余前提；推进到下一连接。

例：`Certificate x → Desired x` 型定理只有当工程能对每个所需原始输入构造 `Certificate x` 时才有用。补上构造并接通调用方，是不同于证明该条件定理的独立成果。内核检查不会因为参数类型名字吉利就消解参数。

不要拿计时器、重复的无变化构建或重复调用模型当进度。具体失败后换一条有依据的表示或证明路线；无法收尾时精确保留 blocker。区分三种失败：实现失败 / 中间命题失败 / 整条方法受阻。退役一条路线要记录原因——否定该路线不等于否定原定理。并行探索在"各路线可能因不同原因失败"时最有价值。

## 3. 让计算携带已证明的解释

区分四类东西：有限例子、对已证定义域的穷举、已检证书、符号/一般证明。有界搜索只是关于所搜输入的证据。穷举有限验证要成为证明，必须同时建立覆盖、编码对应与验证程序本身，且用户约束允许。端到端 Lean 结果的覆盖与解释必须落在声明基础下已证的依赖链内；**注释里说"这个有限列表是穷尽的"，不会把已检列表项变成全称 Lean 定理**。

数值论证在需要精确处用精确算术；先证明真实对象/事件与有限数据之间的连接，再使用数值结论。写清要紧的约定：有序/无序对、重数、下标、零情形、舍入。

按规格与工程惯例事先约定信任基础。**不得为让不完整的内核级证明显得完整而静默引入公理或编译器背书的计算**；也不得把某个工程对枚举或 `native_decide` 的禁令当成普适禁令。任何额外信任假设都要解释清楚，并说明它是否满足本任务。

## 4. 评审仍不确定的数学义务

按核心工作流运行 A/B/C；阶段触发、packet、对抗提示词、异议处置、续作与停止规则见 [references/adversarial-review.md](references/adversarial-review.md)。这些是数学检查，不是对执行者汇报的信任投票。

如宿主配有独立的证明审计流程，循其既有工件与评审契约；被父级审计调用时，把检查范围与证据返回给那次运行，不再递归套娃。独立的 Lean 任务不自动要求再走一遍论文审计流程。需要定向讨论与修复循环时，可调用 `research-review` / `auto-review-loop`，评审路由遵循本仓评审独立性约定。

直接咨询模型时用当前宿主实际可用的工具及其真实契约，问具体问题："翻译这条声明""消解这些调用方假设""给这个新引理找反例""检查这条归约的覆盖"。保留原始回复、真实读取/执行范围与执行者对每条意见的处置。**模型附和不构成证明**；同家族意见始终是暂定的，跨家族意见是额外的评审证据，不是数学真理证书。

未读的工件、未回答的问题、失败的调用、空回复，都不构成实质评审结论。计划评审不是最终代码评审；读日志不等于执行构建。记录实际被检查的命题/版本。重试只在当前授权与供应商规则内进行；不得把失败在后来成功后改写成通过。

用具体推导、已验证反例、更正或有据拒绝来闭合异议；保留未决争议。被调用的评审循环按其自身的轮次/续作契约执行，不要在它外面再套一层轮询。直接咨询则对变更后的义务复审，在收敛或达到真实可用性/预算上限时停止。未决数学保持未决；被点名但不可用的评审保持 pending。评审分数或轮次耗尽都不是完成证明的规则。

执行侧的文件/Shell 工具用于跑 Lean；有价值的并行证明工作用执行侧的子任务/Agent 能力，按稳定引理接口切分并在真实调用方集成。A/B/C 用本技能的数学 packet，不需要论文、发表分或新评审服务。

## 5. 验证真正的最终目标

准备最终构建、信任审计或可移植包时读 [references/verification-and-handoff.md](references/verification-and-handoff.md)。

完成交付要建立以下适用证据；已证定理与仍未完成的复现/评审要求分开陈述：

- **命题确有证明**：检查导出声明的真实类型，而不是关键词——`theorem`/`lemma`/`def` 都可能供给目标命题的证明项。仅定义命题、证 `P → P`、或证别的命题，都不算完成原目标。
- **命题对齐**：展开类型与定义确实表达原始主张；除原始主张自带者外，不给用户留任何内部 profile、证书有效性、覆盖或成功前提。
- **真实装配**：归约、分情形、见证与回到原始结论的通路全部接通，调用方假设全部消解。
- **执行过的验证**：显式构建证明目标的模块，并打印其类型与传递公理；多模块工程另以独立 import 审计入口导出。小型自包含文件直接编译加类型/公理输出即可，不为凑一个 import 而新建工程。保存命令、退出码与输出；**构建了别的根模块不算数**。
- **信任记账**：目标依赖链上不得有 `sorryAx` 或未经批准的额外公理；对照预期基础解释实际依赖；要求清单不必恰等于某个固定公理名集合。
- **可复现性**：保留相关源码与钉住环境，给出他人可运行的命令。
- **所要求的评审**：C 针对最终导出类型、定义体、公理输出与原始主张，不是早先的计划；逐个记录每位所要求评审者的实质结论或不可用。

这些检查确立的是"所述基础下的形式化结果"。文字证明或 HTML 阅读版需要单独的对应性检查——Lean 不为另一载体里的每句话背书。被点名要求的 import 审计、外部复现或评审，可以在定理机检通过后仍处于 pending；按"缺这份证据"如实报告，不把它说成新发现的数学缺口。

一个说明性审计能区分 `available_interface : Target → Target` 与 `original_proof : Target`——即使两者都无额外公理编译通过：前者让原始主张仍开放，后者在 `Target` 与用户命题一致时给出证明。评审调用失败改变不了任何一个的类型。

## 6. 持久化并移交实际取得的证据

复用既有规格、证明台账与续作文件。一份简短进度报告加 Lean 源码、锁文件、审计入口与日志通常足够；只在有具体读者或执行需求时新增文件。

按事实分项报告，不合并成一句含混的 PASS：

- 原始定理：机检通过 / 部分完成 / 仅改述命题 / 已被已验证反例推翻；点名声明与剩余义务。
- 命题对齐与实际逻辑信任基础。
- 复现：增量构建 / 干净重建 / 他人独立复现——以实际发生的为准。
- 评审：谁读了什么、谁跑了代码、哪些被要求的评审仍 pending。

未完成时，保存最小剩余数学/Lean 义务、已知依赖、最后一条有用报错与下一步。已完成时记录完成，避免下次会话复活陈旧缺口。用紧凑续作笔记，不另建第二套状态系统：

```text
原始目标与来源：
当前导出声明 / 主模块：
已闭合连接与真实构建证据：
下一未闭合义务或完成：
A/B/C 评审：来源范围、评审者、原始记录、遗留问题：
下一步：
```

从实际工件解析当前状态，不听信旧的"完成/未完成"叙事；续作先查变更再动手。不把历史与当前评审范围合并成更大的宣称审计。

项目若有研究台账/维基，按其既有流程以精确证据与范围更新受影响主张；不覆写其生成图，不发明第二套验收格式。文献检索为解决数学缺口、API 疑问或相关先行结果服务，不变成"必须穷尽文献"的无关要求。

移交时给出：面向读者的证明、源码、钉住依赖、独立审计命令与已知信任边界。需要单文件阅读版且库内有相应渲染技能时调用之。数学源变更必须重做相应构建与命题/公理检查；Markdown/HTML 里改了定理或假设同样是命题变更——重跑对齐与受影响的所要求评审；保布局保措辞的改动只需展示层检查。变更史留在研究记录里，成品证明直接呈现。**不要为了满足流程仪式而重启已完成的证明工作。**
