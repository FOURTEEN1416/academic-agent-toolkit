# 文档与架构治理

本仓库是全学术Agent系统。治理对象为活跃代码、技能、模板、目录和主控契约，不把数模竞赛或绘图子域当作整体系统。

## 实施原则

1. 先读清实际内容和调用者，不能按文件名猜用途。明确哪些是当前规则、实际实现、业务知识与原始历史证据。
2. 发现矛盾活跃规则直接统一正文，不靠“以另一份为准”保留冲突；原始日志不改写，但不参与执行。
3. 重构按所有权迁移：入口负责路由、技能负责单步领域工作、execution负责实际操作、engine负责状态与验收。迁完调用后删除无用旧实现，不留转发壳或死代码注释。
4. 删除前备份可恢复内容、列清失去的能力和所有引用，删除后核实调用零残留。不得把真实科研成果、原始数据、历史数据库或项目记录当作垃圾。
5. 测试是回归底线；必须以真实受影响业务产物、操作次数和恢复路径检验改造，不用测试数量替代结果。

## 单一真源

| 内容 | 路径 |
|---|---|
| 当前执行契约 | `academic-toolkit/AGENTS.md`、`engine/agent_protocol.py` |
| 模板与业务产出要求 | `engine/modex-core/templates.json`、质量检查实现 |
| 能力与资源 | `capabilities/catalog.json`、`data/asset_catalog.json`、技能路由索引 |
| 当前计划 | `dev-docs/task_plan.md` |
| 历史操作与原因 | `dev-docs/LOG.md` |
| 测试统计 | 根 `pytest.ini` |

## 新能力融入

新增技能必须有专业输入输出、真实执行入口、必要业务检查、来源许可和实际验收。模板编排到单步技能；不让入口技能重复创建嵌套流程。清单、返回码、摘要与执行证据由程序记录，技能正文不再要求模型手写STEP_MANIFEST或重复跑shell占位核查。

## 长文档与技能结构

保持专业知识、示例和参考，不把必要领域推理删成空壳。主文件过载时按主题移到明确引用的参考材料，避免平行规则与重复所有者。风格指引见 `references/skill-writing-paradigm.md`。

## 验证

运行实际受影响业务链、源码引用检查、仓库回归、溯源和健康检查。当前事实直接写入活跃契约；历史过程仅追加到LOG，不反复在活跃文件堆日期补丁。未实现的能力明示缺口，不用备注包装成已完成。
