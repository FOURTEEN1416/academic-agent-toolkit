# 创新点合同（comp-paper-zh / comp-paper-zh-docx 共用真源）

> 本文件是创新点判据的唯一真源；写作技能只引用，不复制判据正文。

1. **条数 2-4 条。** 宁写 2 条实的，不凑 5 条空的。
2. **每条三段式："常规做法 → 本文做法 → 差别"。** 常规做法写清替代路线（文献常用 / 教科书默认 / 上一问的基线）；本文做法写本题的具体改动；差别写它改变了哪个指标或哪个决策。
3. **差别必须带证据，至少一项：** (a) 与 baseline 的指标差值（绝对或相对）；(b) 消融——去掉该改动后退化多少；(c) 与下界 / 理论界 / 独立复算的对照。数字与 `RESULTS.md` 的 `## 发现账本（FINDINGS）` 同源，禁止现编。
4. **保持在建模与求解层面。** 写"用什么机制解决了什么困难"，不写工程流程或通用优点（"用了机器学习""做了灵敏度分析""代码模块化"都不算）。
5. **换题也成立的表述不算。** 判据：把本题的方法名、数据、场景换成任意另一题仍成立 → 不是本题创新，删掉或下沉为模型优点。
6. **落点。** 可独立成小节、并入模型评价、或写在结论章；但正文必须出现一次完整三段式，摘要的"创新点"要素与之同源、不得另起口径。
7. **正例 / 反例。** ✓「把问题一的评分注入问题二的目标函数，两问从串联变协同，总成本比独立求解低 9%（账本：问题二 baseline 差值）」；✗「本文使用了梯度提升树并做了灵敏度分析」（换题仍成立，且没有差别证据）。
