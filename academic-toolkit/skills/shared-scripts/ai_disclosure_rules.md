# AI 工具使用声明与独立支撑材料（CUMCM 2026）

> 依据全国大学生数学建模竞赛官网发布的《全国大学生数学建模竞赛人工智能工具使用规定（2026年试行）》执行：
> https://www.mcm.edu.cn/html_cn/node/fef94648f2836ab6cc81586f4c38512b.html

本规范只在 `CLAUDE.md` 含 `MH_AI_DISCLOSURE=used` 或 `MH_AI_DISCLOSURE=none` 时执行。没有标记时完全跳过。若出现 `MH_AI_DISCLOSURE=invalid`，立即停止本步并报告“需要用户重新确认真实 AI 使用记录”，不得猜测、随机生成或沿用旧版记录。

## 不可变边界

1. **声明是事实记录，不是创作素材。** 唯一事实来源是 `.mh/ai_disclosure.json`；不得增加、删除、替换或美化其中的工具、模型、日期和用途。
2. **只允许白名单内的国产 AI 工具。** 不得写 Claude、ChatGPT、OpenAI、Gemini、Copilot、Llama、Mistral、Grok、Perplexity 等境外工具或模型；型号必须与所选国产工具相匹配，也不得把国产模型名随机化。
3. **用途只能是用户已勾选的辅助环节。** 当前允许：语言润色、代码调试、排版检查、参考文献格式整理、术语翻译与校对。交互示例不得包含赛题的模型设计、公式推导、参数选择、数据处理方案、结果生成、结论写作或创新点。
4. **正文与详情分离。** 论文正文只在参考文献前放一段“AI 工具使用声明”；详情必须生成工作区根目录的独立文件 `AI工具使用详情.pdf`，不得写进论文附录。
5. **不把 AI 工具列为参考文献。** 2026 试行规定要求的是正文声明和独立支撑材料，不要求把工具混进学术参考文献。
6. **不得让语言模型自由编写详情。** 必须调用确定性脚本。工具、型号、日期和用途只来自用户确认；过程文字由脚本读取最终主稿及公开产物后自适应整理，不接受模型自由扩写。
7. **差异来自真实内容，不来自模型自由改写。** 详情应结合本稿题名、实际章节、主稿格式、可识别的公式/图表/参考文献、符号说明表里的中文含义、关键词以及真实存在的代码和结果文件；某项内容不存在就不强行补齐，走兜底措辞。不同项目可以是一页或多页，不设固定段数和固定字数。

   脚本为每个用途备了多套句式，**选哪一套由工作区指纹（题名 + 全部章节名 + 公式/图表/文献计数 + 代码文件名）决定**，因此不同参赛队、不同赛题必然落在不同句式与不同选材上，不会出现全网一段套话。⛔ 但这不是运行时随机：同一工作区重复生成必须逐字一致，否则 `--check-only` 的指纹比对会判"未与当前工作区同步"并拒绝交付。**任何时候都不要在这条链上引入时间戳、随机数或路径。**

   ⛔ 写进详情的每一条论文素材都会被登记，`--check-only` 会回到 PDF 文本里逐条反查。因此句式里引用了哪些素材，就只能登记那些 —— 登记了没写进去的词，闸会把合规产物误判成不同步。
8. **工作区变化必须触发同步。** 主稿、章节、代码、图表或参考文献发生变化后，旧详情 PDF 不能继续沿用；`--check-only` 应检测正文范围与过程记录是否仍对应当前工作区。

## 唯一执行方式

先确认主稿类型，再调用脚本：

```bash
AI_DISC=off
grep -q 'MH_AI_DISCLOSURE=used' CLAUDE.md 2>/dev/null && AI_DISC=used
grep -q 'MH_AI_DISCLOSURE=none' CLAUDE.md 2>/dev/null && AI_DISC=none
grep -q 'MH_AI_DISCLOSURE=invalid' CLAUDE.md 2>/dev/null && AI_DISC=invalid

[ "$AI_DISC" != invalid ] || { echo "⛔ AI 使用记录缺少用户确认，禁止生成"; exit 1; }

AI_TOOL=_utils/build_ai_disclosure.py
[ -f "$AI_TOOL" ] || AI_TOOL=skills/shared-scripts/build_ai_disclosure.py

# LaTeX 项目
if [ -f paper/main.tex ]; then
  python "$AI_TOOL" --manifest .mh/ai_disclosure.json \
    --paper-source paper/main.tex --output "AI工具使用详情.pdf" || exit 1
# Word/Markdown 项目
elif [ -f paper/main.md ]; then
  python "$AI_TOOL" --manifest .mh/ai_disclosure.json \
    --paper-source paper/main.md --output "AI工具使用详情.pdf" || exit 1
else
  echo "⛔ 找不到 paper/main.tex 或 paper/main.md"
  exit 1
fi
```

脚本会完成以下动作：

- `none`：在参考文献前插入“本参赛队在竞赛过程中未使用任何AI工具。”，并确保不存在旧的 `AI工具使用详情.pdf`。
- `used`：根据用户勾选的用途生成规定格式的简短声明；扫描当前真实主稿和公开产物，再生成独立的 `AI工具使用详情.pdf`。
- PDF 固定包含四部分：所用工具名称/版本或型号；具体使用目的和环节；主要提示方式与使用过程；采纳、人工修改和核验情况。
- 四类法定信息结构保持稳定，但内容长度和措辞不固定。结合本稿题名、章节标题、图表题注、符号说明、关键词、代码文件、公式和参考文献等可验证信息决定写什么、写多少；同一篇论文里两条记录即便勾了相同用途，措辞也不会重复。
- 第二至四节的条数按"每个工具几条"控制，大致是工具数 × 2~3（1 工具 3 条、3 工具 9 条、5 工具 10 条），一个工具绝不铺开十几条。每工具上限 `_MAX_PER_TOOL`，总预算 `_MAX_ACTIVITIES`，工具多时按总预算往下收每工具配额。
- 配额内怎么分：用途数 ≤ 配额时一个用途一条，富余额度用来把素材足的用途拆成多轮提问（章节分批送审、代码按文件排查、排版按公式／图／表分工、术语按清单分批），每轮的素材和措辞都不同；⛔ 轮数只能由本稿里确实存在的对象数撑起来，素材不够就老实一轮。用途数 > 配额时把用途分组，一条覆盖若干用途，文字里逐个写出来。
- ⛔ 压条数只能靠合并，绝不能丢用途：少写一个勾过的用途就是漏报实际使用情况。每个工具的每个已选用途都必须在某一条的用途列和正文里出现。
- 第一节的工具表严格等于用户填的记录数（一个工具＋型号＋使用日期一行），不参与上面的分配。
- 面向评审的文字用参赛队自己的口吻。⛔ 不写"本文件依据……整理""记录篇幅随本稿内容确定"这类程序自述，也不出现"工作区""可识别章节""公式环境""处图形引用"；数量按人写论文的说法给（章／个公式／张图／张表／条参考文献），章数只算一级标题，不把子节并进去。
- ⛔ **第三节只写提问范围与边界，不得宣称存在逐轮对话实录。** 工具名、型号、使用日期、勾选用途是用户签字确认的事实；但"分了几轮""每轮问了哪句话"脚本读不到（它只看得见论文里有几章、几个代码文件、几张图表）。因此句式一律写成"提问范围限于……""提交的材料为……""所问事项限于……""不含／不涉及……"，不得写成"参赛队分批提出请求""每次只提交一节""先给出定稿段落再要求逐句标注"这类动作实录；条目标签用"环节 X.Y"而非"记录 X.Y"，导语须说明是按环节归纳范围、不逐条复述对话。每条仍必须写明边界（"限于／不含／不涉及"至少出现一处），否则只剩"问了什么"而没有"没问什么"。
- ⛔ 越界闸只查我们自己组的话，先剔掉照抄的论文素材再查：小节名"问题三的求解结果"、代码文件 `model.py` 与 `solve.py` 相邻都会撞上闸的关键词，直接拿整句去查会让这类再普通不过的论文整篇生成失败。
- ⛔ 环境要求：脚本调 `pdftotext` 时已固定加 `-enc UTF-8`。Xpdf 系构建（Glyph & Cog 4.00 等）默认按 Latin1 输出，会把整份中文详情提成空白，从而误判"缺少规定内容"。若某台机器的 `pdftotext` 连 `-enc` 都不支持，脚本会退回结构检查并打 `[WARN]`，不会因为提不出文本就拦住交付。
- 自适应内容不含核心建模、推导、求解、结果和结论类表述，也不把私有目录、命令或内部日志带入支撑材料。
- 同一命令可重复执行，声明不会重复插入，PDF 使用原子替换。

## 结束前阻断检查

```bash
AI_TOOL=_utils/build_ai_disclosure.py
[ -f "$AI_TOOL" ] || AI_TOOL=skills/shared-scripts/build_ai_disclosure.py
python "$AI_TOOL" --manifest .mh/ai_disclosure.json \
  --paper-source paper/main.tex --output "AI工具使用详情.pdf" --check-only || exit 1
```

Word 项目把 `--paper-source` 改为 `paper/main.md`。检查失败时不得把论文写作步骤标为完成。

## 正文声明格式

脚本自动生成，禁止手工改写：

- 未使用：`本参赛队在竞赛过程中未使用任何AI工具。`
- 已使用：`本参赛队在竞赛过程中使用了AI工具，主要用于〖用户确认的辅助用途〗，详细使用情况见支撑材料。`

LaTeX 版使用不编号的 `\section*{AI 工具使用声明}`，不写 `\addcontentsline`，因此不会制造目录项。Word/Markdown 版使用 `## AI 工具使用声明`。两种版本都必须位于参考文献之前。
