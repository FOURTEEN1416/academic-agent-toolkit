# docx 模式公式编号与合法写法约定（单一真源）

> 消费方：`comp-paper-zh-docx` 与 `paper-write-zh-docx` 的「公式」节（2026-11-16 写作族治理批抽取，消除两件重复维护漂移）。
> 适用场景：`paper/main.md` 单文件 docx 模式（KaTeX / MathJax / Pandoc 导出引擎）。

## 铁律

1. **每个独立（块级）公式都必须连续编号，编号一律写在公式内部，用 `\tag{n}`**；引擎自动提取并右对齐显示成 `(n)`。多行块级公式的闭合 `$$` 必须独占一行、后面不许有任何字符。
2. **禁止 `$$ … (1)`**（编号粘在闭合定界符前同行尾）与"闭合 `$$` 后仍有字符"——任何带尾巴的块公式都是错形态。带尾巴的 `$$` 一旦编号不是纯数字（如 `(8′)`、全角 `（5）`、编号后还有字），引擎认不出它是闭合行，会从那一行起一路往后吞，把后续正文、公式、`![](figures/xxx.png)` 图片引用全当成数学内容 → **公式一个字一个字竖排、图片加载失败**（实测事故：一篇论文 17 处块级公式全中招；引擎侧已加固为"以 `$$` 开头即认闭合"，但**写法仍须按 `\tag{n}`**）。
3. `\tag{n}` 是 KaTeX / MathJax / Pandoc 通认的标准写法，右侧照样显示 (1)、(1′) 等编号。
4. **禁止 `\begin{equation}`、`\begin{align}`** —— 引擎不处理这些 LaTeX 环境。
5. **`\[...\]` 也不要用于独立公式** —— 引擎虽能识别，但会渲染成**行内**公式（不居中、不带编号），达不到独立公式的效果。
6. ✅ **`\begin{cases}` 与 `\begin{aligned}` 可以用**（写在 `$$ ... $$` 里面）—— 引擎会转成 OMML，Word 里正常显示。0-1 变量定义和"目标函数 + s.t. 多条约束"这两种写法都靠它们。

## 示例

```markdown
模型可表示为：

$$y_i = \beta_0 + \beta_1 x_i + \varepsilon_i \tag{1}$$

其中 $\beta_0$、$\beta_1$ 为待估参数。多行写法：

$$
\min_{\mathbf{x}} \sum_{i=1}^{n} c_i x_i \quad \text{s.t.} \quad \sum_i a_{ij} x_i \leq b_j \tag{2}
$$
```
