# 数学建模竞赛论文：自适应章节与完整论证规范

本文件适用于 `comp-paper-zh/en` 及其 docx 版本。它约束的是**读者必须看到的内容**，
不是固定的目录或小节名称。

## 0. 总原则

- 所有数学建模竞赛论文都**不生成正文目录、表目录或图目录**；`stats` 也不例外。
- 先读 `PROBLEM_ANALYSIS.md`、`MODELING_REPORT.md`、`RESULTS.md`，再设计章节。
- 章节跟着“问题依赖链”和“模型类型”走，不跟模板编号走。没有内容的小节比没有小节更糟。
- 上游已经建立的核心公式不得在成文时全部压成行内公式或散文；也不得为了公式数量新编模型。
- 后一问若扩展前一问，只写清**保留了什么、新增了什么、为什么新增、结果改变了什么**，
  不把前一问整套模型复制一遍。
- 页数只用于最终规则提示，不能反向支配建模深度。不得因为页数预估而删核心推导、缩正文字号、
  压小图或把应在正文解释的数学关系塞进附录；生成阶段允许超过参考页数，最后再按用户选择处理。

## 1. 先整理建模—论文映射

正式写正文前，在工作草稿中为每个子问题列一行（不要求把这张表放进论文）：

| 子问题 | 回答目标 | 模型类型 | 变量/状态 | 核心关系/目标 | 约束/边界/假设落点 | 求解产物 | 结果依据 | 复核方式 |
|---|---|---|---|---|---|---|---|---|

填写规则：

1. 公式优先从 `MODELING_REPORT.md` 提取，包括其行内数学关系；报告遗漏而实际求解代码已实现的估计量、判据或边界，应对照代码还原数学定义，先补入工作草稿并标记来源，再用于正文。不得自创未实现模型，报告与代码冲突时先厘清差异。数值只从真实结果、JSON 与表格提取。
2. 任一行缺“结果依据”时不能先写结论；缺少复核方式时，应补真实对照或在论文中诚实说明局限。
3. 这张映射决定正文章序：前一行产物被后一行使用时，两章必须相邻或显式交叉引用。

### 逐问保留数学表达，不以图数替代建模

先安排每问的变量、核心关系与求解条件，再嵌入结果图。映射中的每个数学关系必须落到本问的编号展示公式，或真实存在的公共公式引用；短符号定义可以行内书写。定性任务无需凑公式，不设置每问统一公式数量。

- 几何/网络问题写清对象、距离/邻接与可达判据；不能只列代码函数或展示轨迹。
- 概率仿真问题写清随机机制、事件指示量、实际估计量和采用的区间/误差定义。不是写出“蒙特卡洛”“Wilson”两个名称就完成数学表达。
- “满足可靠度时求最低用量/容量”是反问题优化，必须表达决策量、极小目标、可靠性条件和搜索判停依据；不要误当成纯图表解释题。
- 同一数学关系在公共章已定义时引用其稳定编号并说明本问如何代入；不要重复整套公式。Word 同样使用独立数学块与可追溯的公式编号。
- 只针对真实缺口补充；不要重跑已有计算、增加统一公式配额或附加多轮模型审查。

## 2. 章节怎样自适应

### 先按依赖关系决定“合并还是拆章”

从建模—论文映射表逐行判断，不按“每问固定一章”机械编号：

| 情形 | 章节处理 |
|---|---|
| 多个子问题共用同一份数据清洗、变量口径或基础机理 | 前置为一个公共短章，后文只引用，不重复粘贴 |
| 后一问只是给前一问新增一个约束、情景或目标 | 放在相邻小节，先写“保留/新增/改变”再给增量公式 |
| 后一问更换了决策变量、状态方程或求解范式 | 单独成章，并在开头说明为什么不能沿用前一模型 |
| 一个子问题同时含模型建立、求解和局部检验 | 在同一内容章连续论述，避免拆成三个空章 |
| 一组验证同时覆盖多个模型 | 独立检验章；否则检验紧跟对应模型结果 |
| 结论只有重复摘要与通用优缺点 | 压成短结论，不为“完整结构”强行拉长 |

章节数没有统一答案。判断标准是：读者从章名和相邻关系能否看出“输入从哪里来、建立了什么、
输出交给谁、证据在哪里”。

### 可合并的前置内容

“问题重述”和“问题分析”可以合成一章；“模型假设”和“符号说明”可以合成一章。
不要大段复述原题。前置内容的任务只是给后面的模型定口径、说明依赖关系和必要假设。

### 模型假设的职责边界

- 只保留会影响可行域、状态转移或结果解释的现实简化，通常 4--5 条、最多 6 条；每条由“假设内容 + 一句合理性说明”组成。
- 使用“（1）（2）……”短标签。不要使用“假设 A1/H6”一类内部编号，也不要用过长标签挤压正文宽度。
- 参数数值/区间放在参数或数据说明处；目标函数、Pareto/加权/求解器选择放在模型与求解章节；结果、误差和收益放在结果讨论。
- 程序开关、内部字段、运行状态、检查结论和“无需重写求解逻辑”等工程表述不得进入论文。
- 只有题面未完全规定且建模必须补足的条件才叫假设；题面已知事实、变量定义和问题间的任务分工都不重复包装为假设。

### 符号表与约束的职责边界

- 符号表只收录跨段反复使用、直接进入核心目标或约束的数学符号，通常 12--20 个、原则上不超过 25 个；临时下标、一次性派生量在首次出现处解释。
- 数据列名、函数名、代码变量、校验器名称不得充当数学符号；需要对应数据字段时，在正文首次出现处说明一次映射即可。
- 符号表不承载约束体系，不出现 H1--H16、函数名或“全部通过”等程序检查内容。
- 数学约束必须放在它实际服务的子问题模型中，与变量、目标和现实含义一起解释；程序检查记录不进入论文。
- 符号说明章节固定为“标题 + 一句简短引导 + 符号表”。引导句只说明表中收录的是跨章节复用的
  核心记号；表后不再写总结、约束说明或章节过渡，避免长表跨页后把尾句单独遗留在空白页。

### 主体章节按实际模型命名

章名应回答“本章建立了什么、解决什么”，例如：

- `基于储能状态递推的园区能量调度模型`
- `考虑时窗与容量耦合的多目标配送模型`
- `基于掩码 NMF 的缺失数据补全与验证`
- `动量指标构造、统计检验与跨比赛验证`

不要使用连续多章的空标题：`模型建立`、`模型求解`、`结果分析`。如果内容短，可以在同一章里
连续完成建模—求解—结果分析；如果内容复杂，再按本题的真实概念拆小节。

### 国赛多问题论文保留“题号导航锚点”

“自适应章节”不等于隐藏题号。对 CUMCM 等按问题一、问题二……设问的竞赛，评委必须能在一级标题
中立即定位每一问；一级标题统一使用“**题号 + 本题模型/任务**”的双层语义，例如：

- `问题一：基于空间相交判据的有效遮蔽时长模型`
- `问题二：考虑时间窗与容量耦合的配送路径优化`
- `问题三：需求不确定性下的鲁棒调度与方案比较`

不得只写“问题一”，也不得只写模型名而让题号消失。多个问题共用的假设、数据处理或基础机理可放在
前置公共章；若后一问只是增量扩展，可与前一问相邻组织，但仍要保留自己的一级题号标题。只有不按
“问题 N”设问的统计建模/学术研究型任务可免除此规则。

### 验证、灵敏度、评价是否独立成章

- 某个检验只服务于一个模型：紧跟该模型结果，读者最容易核对。
- 多个问题共用同一组鲁棒性/敏感性实验：可单独成章，但逐项指回受检模型。
- “模型评价与推广”有实质内容时保留；只有通用优缺点套话时并入结论。
- 创新点可以放在对应模型首次出现处或结论中，不强制另设一章。

## 3. 不同模型类型必须露出的数学骨架

下面是**内容槽位**，不要求机械切成同名小节。

### 优化、调度、选址、路径、配比

必须能辨认：决策变量及类型理由 → 目标函数 → 约束与变量域 → 求解方式 → 可行性/最优性证据
→ 结果解释。目标函数与约束必须分开，成组约束用展示公式，不能把全部内容塞进一个自然段。
同一现实机理下的多条约束默认用一个 `equation + aligned` 共用组号；守恒、状态递推、终端条件等
会被单独讨论的机理再独立编号。论文不得暴露 `C1/C2`、`H1/H2` 等内部检查标签。
每个优化子问题必须有自己的展示型目标和约束组，或用稳定公式引用明确说明沿用哪些前序约束，
并只展示该问新增或改变的约束。

按问题实际类型进一步展开，但不要套错骨架：

| 优化类型 | 正文至少应露出的本题数学关系 |
|---|---|
| 线性/整数/网络优化 | 集合与索引、变量域、成本/收益分解、完整目标、逐类约束、可行性与界/Gap |
| 路径/排班/调度 | 指派或弧变量、先后/流守恒、时间递推、容量与互斥、目标构成、冲突/迟到校验 |
| 多目标优化 | 各子目标的现实含义与量纲、归一化/权重或 Pareto 机制、折中解选择依据、权重敏感性 |
| 鲁棒/随机/机会约束 | 不确定量与信息来源、场景/集合/分布、确定性等价或鲁棒对应、可靠度与代价的权衡 |
| 动态决策/控制 | 状态、控制、状态转移、阶段成本、边界/终止条件、策略或滚动更新、轨迹验证 |
| 连续/几何优化 | 坐标与几何对象、可行域、距离/相交/曲率关系、极值条件或数值搜索、边界情形校验 |

算法名称不能代替模型。正文的重点是“为什么这些变量、方程和约束能表示本题”，不是大段复述
遗传算法、模拟退火或求解器的通用步骤；通用伪代码和完整参数表放附录。

### 机理、动力学、微分/差分方程、仿真

必须能辨认：系统边界与状态变量 → 守恒/机理关系 → 控制方程 → 初始/边界条件 → 参数来源
→ 离散或求解方法 → 与解析解、历史数据或基准情形的验证。

### 统计、预测、机器学习、降维

必须能辨认：样本与特征口径 → 数据划分/缺失处理 → 估计量、损失函数或核心变换 → 参数选择
→ 评价指标 → 外部/留出验证与误差分析。不要只讲算法名称和流程图而隐藏实际数学定义。

### 评价、排序、决策分析

必须能辨认：指标为何进入 → 正负向与量纲处理 → 权重来源 → 聚合/排序公式 → 稳健性或权重敏感性
→ 排名的现实解释。权重不可只给数值不讲来源。

### 几何、图论、排队、概率模型

必须能辨认：对象与坐标/节点/随机变量定义 → 核心关系或转移规则 → 可行域/分布假设 → 求解量
→ 极端情形、仿真或现实样本检查。

## 4. 每个核心问题的完整论证

评委读完一个问题章，应当能回答以下六件事：

1. 本章究竟回答了题目的哪一问；
2. 模型中的量分别代表什么，假设在哪里被使用；
3. 核心公式如何从题意/机理/统计目标得到；
4. 代码或求解器实际求了什么，而不是算法教科书原理；
5. 得到了哪些可复核的数值、方案或规律；
6. 结果在什么范围内成立，以及它与基准、误差、容量余量或参数变化之间有什么关系。

若六项中的第 3、5、6 项任一缺失，这一章不能定稿。

### 建模推导链（防止“列一个公式就直接给结果”）

对每个非平凡模型，正文按以下逻辑自然展开；这些是证据层次，不要求机械切成同名小节：

1. **理论/机理起点**：说明采用哪条守恒律、概率事件、几何关系、统计目标或优化原则，以及它为什么适合本题；
2. **题意映射**：把题目对象映射为变量、状态、集合和参数，说明单位、下标和可观测/决策属性；
3. **原始关系**：先写最直接的物理、几何、概率或业务关系，给出必要假设；
4. **推导与闭合**：展示从原始关系到可计算模型的关键变形、离散、线性化、组合或条件分支；
5. **完整模型**：汇总目标/控制方程、约束/边界、变量域，不让关键条件散落在纯散文里；
6. **求解与讨论**：说明实际求了什么、关键设置来自哪里，并用真实结果讨论误差、边界、差异和适用范围。

理论必须落回本题，不能复制教材定义充字数；公式必须推动变量关系、求解或结论，不能为了密度堆公式。

### 内部检查与论文正文必须分层

程序仍要在内部检查容量、时限、守恒、数值残差、数据泄漏和结果一致性，但这些是生成过程，不是论文内容。
正文不得出现内部函数名、断言状态、报告文件、质量门或“检查全部通过”式日志，也不要单设“约束验证”、
“质量检查”“能力审计”“可证伪断言”等工程化标题。

只有能帮助评委理解模型的检查结果才进入正文，而且必须改写成自然的学术叙述：

- 不写“`validate_constraints` 全部通过、容量零越界”，写“最高利用率为 0.992，仍保留 0.8% 的容量余量”；
- 不写“代码内置单调性断言成立”，写“权重由 0 增至 20 时，迁移比例由 0.549 降至 0，说明时延惩罚按预期抑制远距离迁移”；
- 不写“模型未发生降维失败的铁证”，直接解释观察到的变化为何符合模型机理；
- 若内部检查只有“没有报错”而没有新的数学或现实含义，正文完全不提，将细节留在内部报告或附录。

模型约束本身必须完整写进建模部分；求解后是否满足约束则用结果数值自然体现，不把论文写成验收报告。

## 5. 公式选择与排版

- 核心模型公式使用 `equation` / `align` / `cases`（docx 使用独立 `$$...$$` 块）。
- PDF/LaTeX 正文中的展示公式必须有可见编号：使用非星号的 `equation`、`align`、`gather`、`multline`
  等环境；禁止 `equation*`、`align*`、`\\[...\\]`、`$$...$$` 等无编号展示形式。成组目标或约束可以
  用一个 `equation` 包住 `aligned`，也可以让 `align` 逐行编号，但同一组内必须保持一致。
- 后文会引用、比较或作为推导起点的公式必须同时设置稳定的 `\\label{eq:...}`，并用 `\\eqref{...}`
  引用；不能手写“式(7)”这类会随增删漂移的编号。纯行内短定义不要求编号。
- 行内公式只用于符号、短定义和引用，不能承载整套目标与约束。
- 数学式使用短而稳定的符号（如 $p^{\mathrm{buy}}_{r,t}$），不得直接塞入 `GridPurchase`、`AvailableRenewable` 等代码标识符；数据字段只在文字中做一次映射。
- 一个显示公式只承担一个逻辑任务；长目标或约束用 `aligned`、`split`、`cases` 或 `multline` 主动换行，禁止把两条长公式并排。
- 每组公式之后解释新符号、现实含义及它解决的建模困难；不要逐字符朗读公式。
- 只保留支撑结论的核心推导。长代数、伪代码、参数全集、完整代码进入附录。
- 若 `MODELING_REPORT.md` 有大量展示公式而正文几乎没有，视为“建模证据丢失”，必须返修。
- 对上游本来就有数学模型的每个问题，正文至少要同时看得到“定义/状态关系”和“控制方程、目标或约束”
  两类数学证据；若上游只有一类关系则如实保留，不得编造第二类。
- 编译日志中任一 `Overfull \\hbox` 超过 5pt 或出现 `Missing character` 都是发布阻断项，必须修复后重编。

## 6. 结果证据与叙述一致性

- 图表是证据，不是章节骨架。先提出判断，再用数值/图表印证。
- 前序规划阶段只生成能解释“建模过程、求解过程、结果依据或检验过程”的图；凡本轮实际生成到
  `figures/` 的图都必须进入正文对应问题章，不得遗留。若两张图信息重复，应在绘图阶段合成多面板图
  或重做规划，而不是写作阶段丢图。
- 每张正文图都必须形成“**图前问题/判断 → 图 → 图后证据解读 → 下一步衔接**”链。两张独立图之间至少有
  一个完整正文段落，包含该图独有的关键数值/趋势、比较对象和推论；不得形成只有 caption 的图册式连排。
- 多张图共同回答同一判断时，优先在绘图阶段合成有 (a)(b)(c) 标签的单个多面板图；若必须分图，逐图解释
  各自增加了什么证据。不能把“见图 X”当过渡文字。
- “上升、下降、峰谷、最优、显著、稳定”等方向性判断也必须来自真实结果，不能套行业常识。
- 涉及两组时序关系时（例如充/放电与电价），必须计算加权均值、相关系数、峰值时段重合率等至少
  一项可复核量；不能只看图形就套“谷充峰放”之类的行业常识。
- `FIGURE_REPORT.md` / `FIGURE_HTML_REPORT.md` 只作为图表索引和线索；数值与方向仍须回到 JSON、
  表格或代码结果核对。报告措辞与计算结果冲突时，以可复算结果为准并修正报告。
- 图表的证据必须同时匹配题号、情景、参数、样本量与统计口径。追溯生成脚本实际读取的数据文件及字段；不能用另一情景的收敛图证明本情景的可靠性门槛。跨问题对比可以保留，但须说明可比条件和论证边界。
- 图表阶段得到的新发现必须写入可读报告/JSON 后再进入论文；无法溯源的解释删掉。
- 摘要、问题章、结论对同一模型与数值必须一致；最终方向改变后，前文也要同步更新。

## 7. 定稿判据

- 章节标题反映本题模型与任务，而非统一占位名；
- 对按问题编号设问的竞赛，一级标题同时包含“问题 N”和本题模型/任务名；
- 每个子问题完成建模—求解—结果—解释的自然论证；
- 前序核心公式得到选择性保留，没有“全变散文”，也没有公式灌水；
- 优化模型能找到目标和约束，机理模型能找到方程和边界，统计模型能找到估计/损失和验证；
- 不生成正文目录、表目录或图目录（`stats` 也不例外）；
- 页数参考值不触发自动压缩或质量阻断；若赛事有官方上限，只在最终报告中明确提醒用户；
- 自动检查只决定是否继续修订；检查文件名、检查项和通过状态不进入论文正文。
