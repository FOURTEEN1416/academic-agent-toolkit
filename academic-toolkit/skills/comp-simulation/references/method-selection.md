# 方法选型：详版决策树与反模式

## 一、三个判据定位方法

按顺序问，第一个答"是"的即为首选：

1. **系统的"个体性"是核心吗？**（个体异质、个体间交互决定宏观结果）
   → **ABM**。典型信号：博弈、模仿、传染、涌现、跟风、协同/竞争、网络效应。
2. **系统的"流程性"是核心吗？**（资源有限、排队、工序、状态跳变）
   → **DES**。典型信号：产能、周转、拥堵、瓶颈、调度、排队长度、利用率。
3. **系统的"存量-反馈"是核心吗？**（总量之间的反馈回路、政策杠杆、时滞）
   → **SD**。典型信号：库存-产量回路、人口-资源、投资-产能、政策时滞。
4. 都不是 → **连续系统**（微分方程演化）或 **蒙特卡洛**（只关心不确定传播）。

## 二、方法组合矩阵

| 组合 | 何时用 | 角色声明 |
|---|---|---|
| ABM + 蒙特卡洛 | 个体规则含随机、要输出分布 | 机理=ABM；抽样=MC |
| ABM + 优化（pymoo） | 群体调度方案寻优 | 机理=ABM；优化器=pymoo |
| DES + 优化 | 产线/物流参数寻优 | 机理=DES；优化器=pymoo/OR-Tools |
| SD + 校准（PyMC） | 政策情景需参数后验 | 机理=SD；校准=PyMC |
| 数据模型 + 仿真底座 | 数据驱动赛道 | 数据层=sklearn/PyMC；仿真层=任一类；必须保留显式时钟 |
| RL 训练在仿真环境里 | 智能决策策略学习 | 环境=自研/Mesa；学习=stable-baselines3 |

## 三、反模式（选型阶段就要拦）

| 反模式 | 为什么错 | 正解 |
|---|---|---|
| 用 ABM 做一个本质是排队的问题 | 个体性不是核心，白增自由度与不可复现风险 | 用 DES |
| 用 DES 做本质是反馈回路的问题 | 回路需连续反馈，事件跳变表达不了 | 用 SD |
| 只有 ML 没有仿真时钟 | 退化为普通数据建模，赛道定位不符 | 补显式演化过程 |
| 为"用某库"而选方法 | 方法服从问题，不服从工具 | 回到三判据 |
| 单一情景报结论 | 随机系统单次实现无统计学意义 | N 次 + 置信区间 |
| 无基线对照 | 提升百分比无参照 | 至少一个更笨的对照 |
| 参数未校准却宣称"精确" | 校准缺失被包装成精度 | 如实标注"未校准" |

## 四、赛时时间预算参考（4 天赛事）

| 阶段 | 建议占比 | 产出 |
|---|---|---|
| 选型 + 五要素 + V&V 计划 | 10% | `SIM_MANIFEST.json` 骨架 + 选型论证 |
| 最小可运行模型（MVP） | 25% | 能跑通、有观测量 |
| 校准 + 验证 | 20% | 参数表 + 验证记录 |
| 实验设计 + 批量运行 | 25% | 结果账本 + 演化/情景图 |
| 敏感性 + 稳健性 | 10% | Sobol 排序 + 稳健性结论 |
| 论文 + 视频 | 10% | 交付件 |

> 时间紧时**优先保 V&V 与基线对照**，牺牲情景数量——宁可 3 个情景可信，不要 30 个情景不可信。
