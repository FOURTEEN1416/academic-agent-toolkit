# CUMCM 实战经验库 —— 典型场景 · 决策依据 · 踩坑与避坑清单

> **定位**：把真实参赛过程中**由留痕证实**的经验固化为可复用资产。与 `contest_lessons.json`
> 构成一对真源：本文件给人读（决策叙述），JSON 给机器读（结构化字段 + 强制点路径）。
> **机检**：`python academic-toolkit/tools/contest_lessons_check.py`（双向一致 + schema + 强制点路径在位）。
> **来源**：CUMCM 2026 A 题（中药材热风烘干）真实参赛全链路复盘 + 2026-08 演练复盘。
> **纪律**：每条经验必须绑定一个 `enforced_by` 强制点（代码/规则/模板）。**没有强制点的教训
> 不算沉淀完成**——它会在下一届原样复发。

---

## 一、怎么用（三个入口）

| 时机 | 动作 |
|------|------|
| **开赛前** | 通读 §二（场景→决策）与 §三 P0 级条目，把对应强制点在赛前自检里跑通 |
| **赛中遇症状** | 按 §三 的「症状」列检索，直接跳到 `enforced_by` 指向的工具/规则执行，不重新发明 |
| **赛后复盘** | 按 §四 CL2 逐条落账：现象 → 证据 → 根因 → 强制点；新增条目同步本文件与 JSON |

> 与本库相邻的资产：`data/risk_alerts.md`（20 个现场急救坑，偏赛中操作）、
> `data/case_patterns.md`（题型规律）、`dev-docs/LESSONS_FROM_CUMCM_Practice_2026-08.md`（演练期教训）。
> 本库的独特价值是**把事故追到强制点**，而不是只描述现象。

## 二、典型场景与决策依据（9 个）

场景 = 「遇到什么 → 怎么判 → 为什么这样判」。决策依据一栏是本库最重要的部分：
它让下一届不必重新论证同一条取舍。

### S1 · 附件是图片/扫描件，无法直接读取

- **触发**：打开附件 `.xlsx`/`.pdf` 是截图或扫描件，程序读不出数值。
- **决策**：先跑 OCR 工具；**30 分钟内**拿不到可用结构化数据就换题，不死磕。
- **依据**：开赛首日时间预算最贵，"能不能读"的判定必须封顶；读不出的题会在 Day2 持续出血。
- **强制点**：`academic-toolkit/skills/_utils/data_ingest_check.py`

### S2 · 多条并行产物线给出不同数值：是"冲突"还是"可信度信号"

- **触发**：三套独立实现（不同 agent / 不同程序）对同一问题给出 57.0087 / 57.41 / 56.75 h。
- **决策**：做**内容级逐文件比对** → 同源则合并；独立实现则**融合并显式声明独立复算**，不三选一丢弃。
- **依据**：极差 1.1%（问题三）/0.65%（问题四）落在同一网格离散带内，是任何单篇都给不出的交叉验证卖点；
  丢弃等于销毁本项目最有价值的证据。
- **强制点**：`academic-toolkit/skills/comp-consistency/SKILL.md`

### S3 · 合规风险在成稿晚期才暴露（页数/字号/泄漏）

- **触发**：到 final-audit 才发现正文 32 页 > 30 页硬上限、图内字号 3.8pt。
- **决策**：**门禁前移**——出图后（step 5）与成文后（step 8）各跑一次 `quick_gates`；正式 step 10/11/14 仍跑全量。
- **依据**：压页数=动全文，晚期修复成本最高；早期只需删一段或缩一图。
- **强制点**：`academic-toolkit/skills/_utils/quick_gates.py`

### S4 · 仓库里同时存在多份"看起来能直接上传"的提交件

- **触发**：同一次比赛在 3 个仓库/工作区留下 3 处现行提交包，另有编辑区旧包同名并存。
- **决策**：**隔离归档（可逆）** 而非删除——非唯一源移入 `_obsolete_do_not_submit/` 并放
  `README_勿提交.md`；MD5 登记同步回填全部权威文档。
- **依据**：拿错版本不可逆（上传即定稿），删除同样不可逆；隔离同时消除误取风险并保留回退能力。
- **强制点**：`academic-toolkit/skills/comp-cumcm-package/references/submission_checklist.md`

### S5 · skill 用没用过，赛后靠人工回忆补写审计

- **触发**：审计文档自述"人肉按需取用，没有走每步申报 used/skipped 的闸门"，差距清单赛后才回忆补齐。
- **决策**：每步完成强制申报本步推荐技能的 `used`/`skipped`（skipped 须非空理由），used 必须留真实痕迹。
- **依据**：回忆不可信、不可审计；申报成本一行 JSON，收益是 AI 使用申报素材与能力利用率账本自动沉淀。
- **强制点**：`academic-toolkit/engine/workflow_runner.py`

### S6 · 工具箱自设阈值 vs 官方硬性规定

- **触发**：图 PDF 质量闸 8pt 字号下限是工具箱自设（官方明载"没有统一规定正文字号"），调整后 19 项长期 FAIL。
- **决策**：**区分两类阈值**——官方硬性（不可豁免）与自设偏好（可登记豁免，`gates_override.json` + rationale，降级 WARN）。
- **依据**：FAIL 常态化会稀释真告警（狼来了）；豁免必须留理由，否则等于关掉门禁。
- **强制点**：`academic-toolkit/skills/_utils/figure_pdf_quality_check.py`

### S7 · 审核步骤由执行者自己写结论

- **触发**：执行 agent 同时充当审核申报者，报告"全部门禁通过"。
- **决策**：审核类步骤必须派发**只读子智能体**，申报真实 `subagent_session` 与含真实工具调用的 `commands`。
- **依据**：独立视角曾抓出 2 fatal + 1 major（漏用附件、跨问矛盾、过拟合）与 6 major 图表硬伤，
  全部被"自审 PASS"掩盖——自审恒等于表演。
- **强制点**：`academic-toolkit/engine/workflow_runner.py`

### S8 · 检查点是用户裁决点，不是"推进一下"的关卡

- **触发**：检查点审批异常时直接改数据库状态绕过。
- **决策**：只走 CLI **带内通道**推进；确需人工修复必须记录原因；跳过/伪造/绕过一律显式申报。
- **依据**：改库绕过会让状态与事件链脱节，事后无法复盘"谁在什么依据下放行"。
- **强制点**：`academic-toolkit/engine/workflow_runner.py`

### S9 · 提交时间节点没有前置登记

- **触发**：距 9/13 20:00 撰写截止 33 小时、距 9/14 14:00 上传截止 39 小时才开始交付诊断与收口。
- **决策**：把节点写进交付文档与 `STATE.txt`，按 **T-** 时刻倒排冻结；上传前先跑打包沙演。
- **依据**：收口窗口过窄会把"可选优化"变成"必然妥协"；任何一次重编译/重打包都会把 MD5 登记打回过期。
- **强制点**：`academic-toolkit/skills/_utils/build_ai_disclosure.py`

## 三、踩坑与避坑清单（16 条）

严重度口径：**P0** = 直接失分/取消资格级或证据链整体失效；**P1** = 高概率返工或审计不可用；
**P2** = 体验与健壮性，长期累积成隐性风险。

### P0 级（4 条）

| ID | 坑 | 症状 | 根因 | 避坑 |
|----|----|------|------|------|
| **P01** | AI 工具使用详情整份缺失 | 提交前才发现不存在，正文只有一句"详见支撑材料" | 新规试行 + 模板有硬性项，但工具链无脚本出口（254 技能零覆盖） | 用 `comp-cumcm-disclosure` 生成四节结构 PDF + 机检"声明↔详情"口径一致；唯一真源 `ai_disclosure_rules.md` |
| **P02** | 工作流断链无告警 | 14 步只推进 3 步，后 11 步绕开引擎手工完成，`STEP_MANIFEST.json` 只有 1 份 | runner 无心跳/断链检测，手工步骤无补录通道 | `detect_stalled` 停滞告警 + `backfill_step` 带内补录（只补真实产物，`step_backfilled` 可区分）；解题一律经引擎启动 |
| **P03** | 伪造审核产物 | 手写审核结论 + 编造子智能体 session_id，门禁全过 | evidence 只验格式，不验"是否来自独立视角" | `requires_subagent` + 强校验 `subagent_session` + commands 须含真实工具调用（禁 echo） |
| **P04** | 同名不同物 | 两条稿件线同名：14 图 vs 21 图、28 页 vs 80 页；75 个共有路径仅 9 项字节一致（且全是赛题静态输入） | 工作区落成不写状态、归档不改名；"存在性"被当成"同一份"的判据 | `STATE.txt` 三字段 + 归档改名带来源版本；判据升级为**内容级逐文件比对**（md5 清单留证） |

### P1 级（4 条）

| ID | 坑 | 症状 | 根因 | 避坑 |
|----|----|------|------|------|
| **P05** | 门禁发现太晚 | 32 页超限、图字号 3.8pt 都是晚期才发现 | 页数/字号/泄漏只在 step 10/11/14 跑 | `quick_gates` 前移到 step 5 / step 8；输入缺失一律 SKIP 不计失败 |
| **P06** | 中间产物规格无下限 | LITERATURE.md 5.7KB / RESULTS.md 2.9KB，近似目录级 | 只声明 output_files 存在性，不声明内容规格 | `output_specs` = `{min_bytes, require_any, rationale}` 逐项机检；未声明步骤零影响 |
| **P07** | 推荐技能只荐不强制 | 用与不用零留痕，差距清单赛后才补 | 推荐是"建议"不是"申报项" | C1 强制申报（used ∪ skipped 恰好覆盖清单）+ **used 痕迹绑定**（技能名须出现在命令或产物/输入路径） |
| **P08** | 自设阈值造成 FAIL 噪音 | 19 项长期 FAIL，而阈值是工具箱自设 | 无基线豁免机制，自设偏好与官方硬性混为一类 | `gates_override.json` 豁免 + rationale 降级 WARN；官方硬性项不设豁免口 |

### P2 级（8 条）

| ID | 坑 | 症状 | 根因 | 避坑 |
|----|----|------|------|------|
| **P09** | 模板 sty 双源分叉 | 工程 sty 与仓库 sty 有字体/字号/行距/颜色偏移，无版本基线 | 复制官方 sty 后私改，缺"继承 + 追加"分离 | 官方 sty 加 `TEMPLATE_VERSION`；工程侧 `cumcm2026_local.sty` 只 `\input` 官方 + 追加 patch 段 |
| **P10** | 干净件与历史件同盘并存 | 3 处现行包（13.5MB）+ 3 处历史件（52.7MB）；编辑区旧包与仓库包同名 | 重打包不隔离旧包；文档间 MD5 登记不同步 | 唯一提交源 + 隔离区 README_勿提交.md；MD5 登记共享一套并同步回填（清属性→重打包→回读，幂等） |
| **P11** | 身份线索藏在 PDF 属性里 | AI 详情属性残留 `/Creator=LaTeX with hyperref`、`/Producer=MiKTeX-…`，而机检只扫论文 | 元数据扫描未覆盖包内全部 PDF；清理与打包是两个手工步骤 | 扫描范围含包内所有 PDF；固化"清属性→重打包→回读"并做幂等保护 |
| **P12** | 复现路径与包实况不符 | `params.py` 读包根 `../PROBLEM_FACTS.json`，而文件只在子目录 → 复现失败 | 打包后未按 README 从零走一遍复现 | 打包硬闸含**实跑验证**（建 user_data → 跑 `python 源程序/main.py`），不止清单核对 |
| **P13** | 防死循环保险丝烧断审核本身 | 计数器漏计 `fig_*.png` → 8 张图判 0 张、上限=2，17 次调用后被强制"定稿" | 未区分"开发迭代自检"与"审核验收"；计数范围漏计数据图 | 计数范围扩展 + `--review` 审核模式不累计开发计数、不受上限拦截 |
| **P14** | evidence 命令可被伪命令绕过 | `echo done` 冒充执行，无法区分"执行过"与"声称执行过" | 命令字段只校验"非空 + returncode=0" | 描述性伪命令启发式检测 + 审核步骤 commands 须含 `tools/`/`skills/_utils/` 真实工具调用 |
| **P15** | 检查点审批非原子 | BLOCKED→RUNNING→COMPLETED 分两次 transition，中途异常留半完成状态 | 批准记录与步骤完成不在同一事务 | `transition_step_with_checkpoint` 单事务；`BLOCKED→COMPLETED` 纳入合法转换表 |
| **P16** | 用 `skip_` 豁免静默删除审核步骤 | 传 `skip_review=true` 即让审核类步骤不执行且无痕迹 | 豁免参数被当作"合法旁路"而非"审计对象" | 豁免**只留痕不放行**：存在任何 `skip_` 参数时交付一律 blocked，须以不含 `skip_` 的工作流重跑 |

## 四、交付前硬闸与赛后复盘

### CL1 · 交付前硬闸（上传前逐项，缺一不可）

1. 论文电子版：单一 PDF、≤20MB、不压缩、第一页为摘要页、页码连续、正文 ≤30 页
2. 支撑材料：WinRAR 单包 RAR、≤20MB、源程序同时在包内与附录
3. 身份扫描：文件名/目录名/文档属性全部无身份线索（**含包内所有 PDF**）
4. AI 申报双件套齐备，且正文声明口径与详情用途一致
5. 按 README 从零实跑一次复现路径（建 `user_data/` → 跑 `main.py`）
6. 唯一提交源确认：非唯一源已隔离且带 `README_勿提交.md`
7. MD5 登记已回填全部权威文档，且与实际包一致
8. 时间节点已前置登记，按 T- 倒排冻结

> 强制点：`academic-toolkit/skills/comp-cumcm-package/references/submission_checklist.md`

### CL2 · 赛后复盘（把事故变成机制，而不是变成记忆）

1. 逐条记录缺陷：现象 → 证据路径 → 根因 → 已修复/待修复
2. **每条缺陷必须落一个 `enforced_by` 强制点，否则不算沉淀完成**
3. 区分"官方硬性"与"自设偏好"阈值，自设类登记豁免理由
4. 更新本经验库：新增条目 + 同步人读真源 + 跑 `tools/contest_lessons_check.py`
5. 把可迁移结论并入对应 `SKILL.md`（不留在一次性报告里）

> 强制点：`academic-toolkit/skills/_utils/quality_gate_contract.md`

## 五、维护纪律

1. **双写**：新增/修改条目必须同时改 `contest_lessons.json` 与本文，ID 一一对应；
   机检 `tests/test_contest_lessons.py` 会把不一致打成失败。
2. **强制点必须真实存在**：`enforced_by` 是仓库根相对路径，机检逐条验证在位——
   禁止写"应当建立 XXX"这类无落点的空承诺。
3. **证据必须可回溯**：`evidence` 指向仓库内文件或路径；引不进仓库的结论不收。
4. **一次事故一条**：不合并不同根因的条目；重复现象归到同一条的 `symptom`。
5. **修剪纪律**：条目只能在"强制点已覆盖到更高层机制"时归档，且需在 `meta` 留迁徙说明。

```bash
# 机检（schema + 双向一致 + 强制点在位）
python academic-toolkit/tools/contest_lessons_check.py
# 随 pytest 护航
pytest academic-toolkit/tests/test_contest_lessons.py -q
```
