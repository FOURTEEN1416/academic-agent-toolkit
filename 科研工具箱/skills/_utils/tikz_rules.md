# TikZ 学术图生成规则：语义驱动、自适应布局、可验证成品

本文件用于数学建模与科研论文中的 TikZ 图。模板和示例只用于学习 TikZ 写法，**不能按论文类型、标题长度、随机数或固定模板编号决定成品**。每张图应先明确它要解释的问题，再由信息拓扑选择图型、方向、层级、配色与尺寸。

真正的硬约束只有四类：

1. 图忠实于题目、模型、推导和真实执行过程；
2. 在论文最终尺寸下仍清楚可读；
3. 节点、边、标签不存在遮挡、误连或歧义；
4. 视觉语言与论文一致，并且不只靠颜色传递含义。

圆角、阴影、蓝色、纵向、13 cm 组框、某个模板编号都不是硬约束。

## 1. 先决定是否该画、该用什么引擎

TikZ 优先用于：

- 需要与正文一致的 LaTeX 数学符号；
- 需要精确锚点、辅助线、角度、路径或边标签；
- 技术路线、流程、依赖、因果或架构关系需要严格路由；
- 几何构造、受力、光路、可行域、相平面、电路等矢量示意；
- 需要在 PDF 中无损缩放并保持字体一致。

不应为了“显得专业”而硬画 TikZ：

- 数据趋势、分布、误差和对比结果优先用真实代码生成的数据图；
- 写实工程场景、实物外观和复杂空间透视优先用可靠的场景图或专业 CAD；
- 纯文本层级且没有公式、跨层边或精确几何时，可用 DrawIO/HTML，但仍遵守本文件的信息和可读性规则；
- 一段正文比框图更清楚时，不画图。

### 1.1 赛题/研究特征 → TikZ 图类型规划触发（FIGURE_MANIFEST 阶段用）

下表是**规划期**判据：命中特征时应在 FIGURE_MANIFEST 里规划对应 TikZ 图；画哪一类图由特征决定，**怎么画仍按本文件后续语义/拓扑规则，不套固定模板编号**（表末列模板编号仅指 `tikz_examples_extra.tex` 里的学习示例）。


TikZ 在"数学符号 + 精确几何"类图上是天花板。遇到下列赛题特征时，**应主动规划对应的 TikZ 图**（这些图 DrawIO 画不了、matplotlib 画得笨拙）：

| 赛题/研究特征 | 应规划的 TikZ 图 | 参考模板 |
|--------------|----------------|---------|
| 线性/整数/非线性规划、优化求解 | 可行域图（约束线+可行域+等高线+最优解） | M |
| 微分方程、动力系统、稳定性分析 | 相平面图 / 向量场 | E |
| 物理力学（受力、斜面、桥梁、约束反力） | 自由体受力分析图 | F |
| 光学（成像、反射折射、激光） | 光路系统图 | G |
| 几何证明、平面几何、向量分解 | 几何示意图（calc） | J |
| 函数拟合、收敛过程、灵敏度曲线 | 函数图像（公式刻度与正文统一） | D |
| 神经网络/深度学习/集成模型架构 | MLP / CNN / Transformer | A/H/I |
| 物理约束建模、PINN、算子学习 | PINNs 架构图 | L |
| 弹簧振子、机械连接、波动/阻尼 | 装饰路径片段嵌入物理图 | K |
| 电路网络、信号系统（电工杯等） | 电路图（circuitikz） | O |

**⛔ 规划提醒**：以前的规划只在"神经网络/变量关系/带公式算法流程"几类触发 TikZ，导致可行域、相平面、受力图、光路图这些 TikZ 最能打的类型被漏掉。现在凡命中上表特征，赛题分析阶段就应在 FIGURE_MANIFEST 里规划对应 `tikz_xxx` 图。

## 2. 出图前先写“图契约”

每张图在 `FIGURE_MANIFEST` 或源码注释里至少明确：

```text
purpose: 读者看完这张图应回答什么问题
topology: linear / hierarchy / parallel / loop / network / geometry / causal / matrix
reading_direction: top-to-bottom / left-to-right / radial / coordinate-based
node_roles: 输入、过程、模型、证据、输出、外部对象……
edge_roles: 数据流、控制流、依赖、反馈、推导、约束……
paper_context: 所在章节、预计栏宽、相邻图的视觉语言
visual_encoding: 哪些含义由形状、线型、文字、颜色分别承担
style_family: G1 / F1 / A1 / C1 / N1 / T1 / M1 / U1 / P1
annotation_policy: minimal / explanatory / comparative
result_policy: none / symbolic / data-encoded
final_width: column / text / full-page
print_mode: color / grayscale / both
```

没有写清 `purpose` 和 `topology` 就开始套模板，通常会得到“节点齐全但逻辑错误”的图。

### 2.1 默认画“单一学术示意”，不要画讲解卡片拼贴

用于正文解释模型机理、几何关系、变量关系或求解构造时，默认只保留一个连续的视觉场景：

- 图内可放辨认关系所必需的数学符号、对象简称、方向、边标签，以及 1–2 个与画面直接绑定的短公式或短说明；不是追求“零文字”；
- 推导步骤、成段解释、结论句、参数表和结果数值放正文或图注，不在图旁再拼一列文字卡片；
- 不把“示意图 + 四步说明 + 结果框”合成演示文稿式信息图；
- 除非结果数值本身就是图要编码的数据，不在机理/几何示意图中硬塞具体数值；
- 多面板只用于比较、尺度切换或互补视图确有必要的情形，并用 (a)(b) 形成一个明确图组；不能仅因内容放不下就左右拼接文字说明。

判断标准：去掉图注后，读者应能看懂对象之间的空间或逻辑关系；完整论证仍由正文承担。图不能代替正文，也不应重复正文。

短公式应贴近它解释的边、角、区域或对象，例如弦旁标注 $\|P_{k+1}-P_k\|=L_k$；不得在空白处堆成一个缩小版公式推导区。短说明通常不超过一行，若需要第二句解释，就移到图注或正文。

## 3. 按信息拓扑选择布局，不按论文题型选模板

| 信息拓扑 | 首选布局 | 适用条件 | 不宜使用 |
|---|---|---|---|
| 3–6 个短步骤的单向过程 | 横向左→右或纵向上→下 | 主链清晰、分支少 | 为了横排把字缩小 |
| 多阶段、多子问题技术路线 | 分层布局，阶段内局部并行 | 每层有明确输入和输出 | 每问机械复制同样流程框 |
| 层级依赖/树结构 | top-down layered/tree | 父子关系明确 | 把一般网络误画成树 |
| 多方案比较后汇聚 | 并行泳道/列 + 显式汇聚点 | 分支执行语义相同 | 用斜线把所有分支拉向一个节点 |
| 循环迭代 | 主流程 + 外围反馈回路 | 有明确终止条件 | 把反馈边穿回主链内部 |
| 真正的中心—辐射关系 | 径向 | 一个中心、有限辐射分支 | 普通流程或时间顺序 |
| 两维分类或职责分工 | 矩阵/泳道 | 行列各有独立语义 | 用颜色假装二维结构 |
| 因果/路径模型 | 因果方向一致的层次图 | 边有清楚方向与系数 | 视觉位置暗示不存在的因果 |
| 几何/物理/推导 | 坐标或构造驱动布局 | 空间关系本身就是信息 | 用通用流程框替代几何关系 |
| 稠密网络 | 自动布局 + 人工微调，必要时拆图 | 边多且非层级 | 绝对坐标逐点硬摆 |

选择方向时看**最终页面**：横向节点多、标签长时转为纵向；纵向层级太深时按阶段分栏或拆成“总览 + 局部图”。禁止先画超大图，再用 `scale=0.5` 塞进页面。

需要选择或组合视觉语法时，读取 `tikz_style_families.md`。它提供几何、机理、流程、架构、因果、网络、时间/状态、矩阵/泳道、可行域和对比图组等样式族，但不提供固定色板或固定节点模板。

### 3.1 推荐的实现机制

- 线性链和少量节点：`positioning` + 相对定位；
- 规则行列和泳道：`matrix of nodes`，显式 `row sep` / `column sep`；
- 层级 DAG：默认 XeLaTeX 管线使用 `positioning`/`matrix` 分层；只有确认 LuaLaTeX 可用时才启用 `graphdrawing` 的 `layered layout`，再做局部微调；
- 动态分组框：`fit` + `backgrounds`，让框根据真实节点边界自适应；
- 几何、受力、光路：`calc`、`angles`、`quotes`、坐标与路径；
- 绝对坐标仅用于几何图、少量精调或坐标本身有数学含义的图。

`fit` 和背景层是 TikZ 官方支持的自适应工具，不得一概禁止。背景必须放在节点之后定义、在背景层绘制，并以最终 PDF 检查是否发生遮盖。

编译器必须先于布局引擎确定：本项目默认命令是 XeLaTeX，而 PGF 的自动 graph drawing 算法需要 LuaTeX。未经能力检测不得在 XeLaTeX 任务中直接生成 `\usegdlibrary`/`layered layout`；稠密网络可改用相对布局、拆图，或在允许的环境中先由 Graphviz 计算坐标再交给 TikZ 排版。

## 4. 自适应视觉语言：不固定颜色，也不随机换皮

### 4.1 先从论文语境选视觉语言

颜色与样式由以下因素共同决定，而不是“某题型固定某套颜色”：

1. 论文模板是彩色还是黑白、最终是否打印/复印；
2. 该图是结构框图、物理示意、因果路径还是数据编码；
3. 同一篇论文已有图表的字体、主色、线型与明度；
4. 图中真正需要区分的语义角色数量；
5. 色盲、灰度和低对比环境下能否理解。

允许的视觉策略包括：

- 纯黑白/灰阶：理论、几何、推导和复印场景常常最合适；
- 单色系 + 一个强调色：结构框图和技术路线常用；
- 少量定性色：确有 3–5 个并列类别时使用；
- 顺序/发散色：只有颜色确实编码有序量或正负偏差时使用；
- 与题材相关的颜色：仅当颜色本身有领域语义，并且仍有文字/线型冗余编码。

**高饱和色不是绝对禁止**：关键状态、危险边界或唯一强调点可以使用，但面积应小、语义明确、对纸白和相邻色有足够对比。禁止的是没有语义依据的“电光蓝 + 青 + 紫 + 橙”拼盘。

### 4.2 使用语义令牌，但令牌取值不固定

结构图应集中定义论文级语义令牌，名称和值都可按项目调整：

```latex
% 只是结构示例；色值应从当前论文视觉语境推导，不要复制固定值
\definecolor{paperPrimary}{HTML}{...}
\definecolor{paperAccent}{HTML}{...}
\definecolor{paperPanel}{HTML}{...}
\definecolor{paperGuide}{HTML}{...}

roleMain/.style={draw=paperPrimary, fill=paperPanel, text=black, ...},
roleAux/.style={draw=paperGuide, fill=white, text=black, ...},
edgeMain/.style={-{Stealth}, draw=paperPrimary, ...},
edgeFeedback/.style={-{Stealth}, draw=paperGuide, dashed, ...}
```

这样做是为了整篇一致和便于统一调整，不是强制 `mhPrimary`、蓝灰色或某组十六进制值。

### 4.3 颜色不能独自承担语义

- 阶段/状态同时用标题、编号、形状、边框或线型区分；
- 数据流、控制流、反馈流至少用实线/虚线/箭头形状之一冗余编码；
- 正/负、通过/失败除颜色外还要有 `+/-`、文字或图案；
- 关键边界、箭头和符号相对背景的对比度目标至少 3:1；
- 正文文字保持高对比，通常使用黑色或近黑；
- 出图后必须做灰度检查；去掉颜色仍无法读懂，判为失败。

### 4.4 同一篇论文统一什么，不统一什么

应统一：正文字体、基础字号、箭头家族、同一种语义角色的形状/线型、主辅色逻辑、图注口径。

不必统一：每张图的方向、节点数、圆角、分栏方式、背景框数量和具体色彩用量。几何图和技术路线图可以采用不同画法，只要读者不会把同一视觉符号理解成冲突的含义。

## 5. 通用信息密度与版面规则

### 5.1 节点内容

- 一个节点只表达一个动作、对象或状态；
- 标题尽量是一行，解释最多两行；长解释移到正文或图注；
- 节点中只放一个短公式或关键符号，不放成段推导；
- 公式和术语复用正文定义，不把 `CamelCase`、`snake_case` 或代码字段直接放入成品；
- 文字长短决定节点尺寸，不能先固定小框再把文字压进去；
- 节点超过约 12 个或边超过约 16 条时，优先拆成“总体逻辑 + 局部细节”，而不是继续缩小。

#### 中文节点宽度计算公式（防遮挡核心）

中文字符宽度约为英文的 2 倍。节点宽度必须按以下公式计算：

```
minimum width = 中文字数 × 0.7cm + 英文字符数 × 0.35cm + 1.0cm（内边距）
```

示例：
- "数据预处理"（5 个中文）→ minimum width = 5×0.7 + 1.0 = 4.5cm
- "LSTM 模型"（4 中文 + 4 英文）→ minimum width = 4×0.7 + 4×0.35 + 1.0 = 5.2cm
- "空间杜宾模型 (SDM)"（7 中文 + 5 英文）→ minimum width = 7×0.7 + 5×0.35 + 1.0 = 7.65cm

**⛔ 如果节点文字超过 8 个中文字符，必须用 `text width` + `align=center` 允许自动换行，而不是加大 `minimum width`。**

### 5.2 最终尺寸可读性

- 一律按**插入论文后的实际宽度**检查，不按独立 PDF 放大后的观感判断；
- 承担主要语义的文字，最终有效字号建议不低于 8 pt；辅助标签一般不低于 7.5 pt；
- `\tiny`/`\scriptsize` 只允许非关键、可由正文完全替代的注记；
- 关键线在最终尺寸下应清楚可辨，避免依赖极细发丝线；
- 图过大时按“缩短文字 → 改方向 → 增大画布占比 → 分层/拆图”的顺序处理，最后才整体缩放。

### 5.3 留白与对齐

- 节点使用真实边界间距，而不是只看中心点距离；
- 相邻节点最小净空应至少能容纳一个边标签或清晰箭头；
- 同层节点对齐基线或中心，层间距要大于同层间距以形成层次；
- 先减少交叉，再减少折点和总边长；不要为了“更对称”制造交叉；
- 组框用 `fit` 自适应包围内容，内边距保持一致；标题放在组框独立标签，不与第一行节点争空间。

## 6. 边与标签：防遮挡的核心

### 6.1 路由优先级

1. 让主流程方向一致；
2. 调整节点顺序消除交叉；
3. 为不同语义流分配独立通道；
4. 用端口/锚点和汇聚点减少扇入扇出；
5. 最后才使用弯曲或跨越。

### 6.2 硬规则

- 边不得穿过任何节点、组标题、公式或关键标签；
- 分层图优先从相应方向的锚点出入，如 `.south`→`.north`；
- 多条边汇入同一节点时，先调整层内顺序；仍拥挤时使用清楚的汇聚点/总线，不画斜线蛛网；
- 反馈边沿主图外侧走，主流程内部不反向穿越；
- 长跨层边应走专用外侧通道，且不与组框边界重合；
- 交叉不可避免时，尽量接近直角、交叉点不放文字，并用 line jump 或局部断线明确谁跨越谁；
- 边标签放在线段旁的稳定空白区，可用接近纸色的薄底与适度 `inner sep`，但不能遮住箭头；
- 同一对节点的双向关系要用两条分离路径或双向箭头加清楚标签，不重叠画两条线。

### 6.3 分支与判断

- 判断节点写成可回答的问题；
- 每个出口都明确标注条件（如“是/否”“满足/不满足”），标签靠近分支起点；
- 分支最终是否汇合必须显式表达，不能靠空间位置猜；
- 循环必须展示终止条件，回路走外围并标明回到哪一步；
- 不使用装饰性的菱形：没有条件分支就用普通过程节点。

## 7. 各类图的专用绘图逻辑

### 7.1 技术路线图

技术路线图回答“整篇研究如何从材料走到结论”，不是把目录装进框里。一般包含：

1. 输入材料/问题约束；
2. 对子问题或研究任务的拆分；
3. 模型、机制或关键推导；
4. 求解、计算与证据；
5. 输出产物及必要反馈。

要求：

- 用“问题一/问题二”等作为导航锚点时，同时写出该问独有的建模任务；
- 子问题独立就用并行泳道，有依赖就画真实依赖边，不能为了整齐全部串行；
- 共同的数据准备、假设或符号层只画一次；
- 验证应连回被验证的模型/求解环节，而不是统一丢到图底；
- 图中只写研究对象、方法、依赖关系和产物名称，不写已经求出的最终数值，也不写“验证通过”“结论成立”“显著优于”“效果最佳”等结果性判断；输出节点只能写“输出最优螺距 $p_{\min}$”这类变量或产物名称，不能写“$p_{\min}=0.450338\,\mathrm m$”；最终数值与结论交给结果图、表或正文；
- 每问已有正文流程时，不再机械生成一张同质化小流程图。

### 7.2 一般流程图与算法流程图

- 遵循统一的开始/结束、处理、输入输出、判断语义；
- 主路径尽量单向；异常/失败路径靠外侧；
- 算法图只展示宏观迭代逻辑和题目特有步骤，不把完整伪代码搬进图；
- 初始化、更新、收敛判据和输出必须与正文/代码一致；
- “精度 $10^{-6}$”“最大迭代次数 1000”等求解设置可以出现，但不能把本次运行得到的最优值、终止时刻、误差、准确率或优劣结论塞进流程节点；
- 并行模型比较要有同一输入、相同评估口径和显式汇聚/选择节点；
- 启发式算法不能只画“初始化→迭代→输出”的通用空壳，必须体现本题的编码、约束处理或邻域机制。

### 7.3 系统/模型架构图

- 先画边界：外部实体、系统边界、子系统/模型层、数据或产物；
- 组件、数据、外部对象和控制器用不同形状或边框语义；
- 数据流和控制流使用不同线型并配图例；
- 箭头标签写“传递什么/触发什么”，不用含糊的“交互”“处理”；
- 神经网络图展示与论文贡献有关的层、残差/注意力/物理约束，不逐神经元装饰；
- 模型融合要画出各分支输入、输出维度或融合规则，不用一个 `Fusion` 黑箱遮住核心。

### 7.4 几何、物理与推导构造图

- 图中明确给定量、辅助构造、待求量；线型语义固定：实体/轨迹/辅助/延长/投影可分别用实线、粗线、虚线、点划线；
- 坐标轴、单位、方向和正负约定与正文一致；
- 角度用弧线，距离尽量在图形外用双向尺寸线；
- 同一点附近的标签向不同方位散射；空间不足时用引线拉到空白区；
- 多步推导用阶段编号、渐进叠加或主图 + inset，不能把十几个中间量堆在同一点；
- inset 必须标明它放大的是主图哪一部分，并保持符号一致；
- 遮住题目只看图，应能辨认这道题的真实构造与推导链；泛化空壳判为失败。

### 7.5 可行域、相平面和函数示意

- 坐标、约束线、可行区域、目标方向/轨迹和关键点必须有清楚图例；
- 填充不遮挡边界与标签；颜色之外用线型/纹理区分；
- 可行域图必须与实际约束一致，不能只画一块“看起来合理”的阴影；
- 相平面应标方向、平衡点与稳定性相关结构；
- 函数示意若来自真实计算，优先由代码生成；TikZ 仅用于解析结构或小型教学式示意。

### 7.6 因果路径、SEM 和变量关系图

- 方向由理论关系决定，不由“哪里有空位”决定；
- 路径系数、显著性与假设编号放在对应边旁；
- 控制变量可分组后用一条明确路径作用于结果变量，避免多条长斜线；
- 潜变量与观测变量用不同形状；误差项、协方差和直接/间接效应不能混用一种边；
- 不在没有识别依据时画成因果箭头，可改用无向关联或文字说明。

### 7.7 网络与拓扑图

- 首要目标是减少边交叉，其次是节点重叠、边弯折与长度；
- 采用适合结构的自动布局后人工微调，不按固定圆环摆放所有网络；
- 只给关键边/节点加标签；大量权重改用图例或单独表格；
- 社群、层级和中心性如果是结论，必须由真实计算支持；
- 超过单页可读密度时采用聚合、分层或局部视图，不缩成“毛线团”。

## 8. 源码与绘制顺序

- 将颜色、节点角色、边角色写成集中样式；
- 节点命名按语义，如 `data_clean`、`model_q2`，不使用 `n1/n2` 作为唯一语义；
- 先创建节点/坐标，再创建自适应组框，再画边和标签；若使用背景层，组框在背景层输出；
- 复杂图按 layer/scope 分区，避免所有命令堆在一个平面；
- 连接节点使用名字和锚点，不把线端点硬编码为坐标；
- 保留一行注释说明特殊路由为什么存在；
- 图源码只包含可公开论文内容，不含内部路径、命令、Skill 提示词或密钥。

## 9. 编译与视觉质量门

每张 TikZ 图都必须作为独立矢量 PDF 编译，并运行：

```bash
bash _utils/tikz_check.sh figures/tikz_xxx.tex 2>/dev/null \
  || bash skills/shared-scripts/tikz_check.sh figures/tikz_xxx.tex
```

之后在论文中以预期尺寸插入，重新编译整篇，逐项检查：

### 9.1 结构检查

- 图回答了 `purpose`，没有目录式堆砌；
- 节点和边语义唯一，没有假连接、死端或缺失输出；
- 判断分支有条件，循环有终止条件；
- 组框没有遮住节点，边没有穿节点或标签；
- 关键图形对象对背景有足够对比，不依赖颜色独自编码。

### 9.2 最终尺寸检查

- 在 PDF 100% 和接近常见阅读缩放下检查文字、箭头和边标签；
- 页面缩略图中能看懂层级，放大后能读清细节；
- 不存在 Overfull、文字截断、公式越界、箭头头部丢失；
- 图没有因为过高独占空页或造成前页大面积留白；
- 灰度打印仍能区分关键角色；
- 图注说明该图独有的信息和作用，不写“如下图所示”的空话。

### 9.3 密图处理顺序

发现拥挤时依次处理：

1. 删除不承担信息的装饰和重复文字；
2. 改变层内排序以消除交叉；
3. 增加真实边界间距、重新路由；
4. 改方向或使用 matrix/手动分层；只有确认 LuaLaTeX 可用时才调用自动 layered layout；
5. 拆成总览 + 局部图/inset；
6. 最后才允许小幅整体缩放，并重新验证有效字号和线宽。

## 10. 自动检查豁免

自动检查只拦截可高置信识别的问题；无法从源码可靠判断的美学问题必须靠最终 PDF 视觉检查。若绝对坐标对几何关系确有必要，或某个特殊视觉编码有学术理由，可在源码写：

```latex
% MH-TIKZ-ABSOLUTE-OK: 坐标本身对应物理几何位置
% MH-TIKZ-COLOR-OK: 高饱和强调色仅表示危险阈值，且另有线型和文字编码
```

豁免必须写明理由，不能用来跳过真实遮挡、越界、错误关系或不可读字号。

## 11. 规则依据

- PGF/TikZ 官方手册的 layered layout 将布局分为去环、分层、减少交叉、定位和边路由；不同图应选择不同启发式，而非固定模板。
- TikZ 官方 `matrix`、`fit`、`backgrounds` 与 graph drawing 用于自动对齐、包围真实边界和路由，不应被一概禁止。
- Graphviz `dot` 同样以保持方向、减少交叉和缩短边为目标，并提供 `nodesep`、`ranksep`、rank 与 cluster 控制。
- 图布局实验表明，减少边交叉是最显著的可读性因素，网格对齐也很重要。
- WCAG 非文本对比建议理解图形所必需的对象与相邻颜色至少达到 3:1，并且不只使用颜色传递信息。
- ISO 5807 规定了信息处理流程图的符号和约定；本规范遵循其“符号有稳定语义”的原则，但不把所有研究图强行画成程序流程图。
